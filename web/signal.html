How it works

Four parts. Four separate jobs.

Traffic flows one way: ESP32 → CAN A → STM32 gateway → CAN B → protected ECU. The analyst watches a copy; the safety task acts only on request. Each step below runs the real engine with a seeded attack.

  1. The ESP32 role generates six signals — 0x120 Brake, 0x130 Steering and 0x200 Powertrain every 20 ms; 0x300 Battery and 0x400 Body every 100 ms; 0x500 Infotainment every 200 ms. Frames from an attack you inject leave from here too, into CAN A’s bounded queue.

    Does
    Offers baseline and injected frames to CAN A.
    Does not
    Decide anything. Its attack labels are used only for scoring.

  2. The gateway checks each frame’s identifier, length, timing, rate, physical plausibility and rolling counter. A frame that fails is blocked and never reaches CAN B. A frame that passes is forwarded to the protected ECU. If a bounded queue is full, a frame is dropped — an availability loss, not a detection.

    Does
    Forwards or blocks every inspected frame; can request degradation.
    Does not
    Learn normal payloads or latch the vehicle’s mode.

  3. The gateway copies inspected payloads to the analyst, which scores them against a model trained on separate clean traffic (40 ms modeled delay). Repeated outliers return as evidence; the gateway may then hold that identifier. Disconnecting the analyst leaves every gateway rule running.

    Does
    Observes copied payloads and returns evidence.
    Does not
    Sit in the forwarding path or block frames itself.

  4. Sustained, confirmed evidence on a critical signal lets the gateway send a degradation request — nothing more. The independent safety task acknowledges it (60 ms modeled), latches the degraded mode and disables the modeled motor. Recovery needs cleared attacks, a 2.5 s quiet interval and an explicit request.

    Does
    Acknowledges, latches and releases the degraded mode.
    Does not
    Filter traffic or detect anomalies.

What does the Raspberry Pi do?

The simulated Pi watches copies of inspected payloads, with a modeled 40 ms delay. It compares signal values with a statistical baseline learned from a separate clean trace.

Three consecutive abnormal observations for one CAN ID trigger a 500 ms hold, renewed if anomalies continue. The STM32 gateway enforces that hold on subsequent frames; the Pi is not in the forwarding path.

Gateway rules still work when the Pi is disconnected. A flood can be blocked for its rate while its payloads look normal to the Pi. Vehicle shutdown is a separate safety decision, not an automatic consequence of a Pi alert.
