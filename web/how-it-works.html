Traffic & CAN

The modeled ESP32 generates seeded vehicle signals and controlled adversarial traffic. CAN A carries offered input to the gateway; CAN B carries forwarded frames to the protected vehicle model. Each segment has a finite 500 kbit/s serialization budget.

Standard CAN arbitration favors lower identifiers. Bounded queues can fill, causing availability loss. A dropped frame is recorded as a drop, not automatically counted as a successful detection.

Two kinds of evidence

The STM32 gateway: local decisions

The gateway checks the identifier allowlist, schema length, timing, rolling-counter freshness, physical bounds and slew. Rate and queue protection constrain overload. These checks continue when the Pi analyst is disconnected.

The Raspberry Pi: payload analysis

A separate synthetic training trace fits the analyst's statistical model. Delayed observations accumulate before the analyst places temporary holds. The analyst evaluates payload evidence; it does not infer an anomaly merely because an attack was selected in the interface.

A battery flood can trigger gateway filtering while its payloads remain statistically normal. The Pi may therefore report no payload anomaly. Read the gateway, analyst and safety assessments as separate results.

The threat score and sequential evidence test combine observed evidence. Scenario names and ground-truth labels are reserved for evaluation and do not drive detector decisions.

Independent safety authority

Detection does not automatically disable the vehicle model. A degradation request requires sustained evidence, sequential confirmation and recent evidence involving a critical signal such as braking, steering or powertrain.

  1. The gateway issues a request when the modeled criteria are met.
  2. The independent safety task acknowledges the request after its modeled delay.
  3. Degradation latches. Stopping attack sources alone does not reset it.
  4. After the quiet interval and recovery eligibility, the user explicitly requests recovery.

The interface shows request time, activation time, eligibility and vehicle state. These are modeled safety boundaries, not a safety certification or an interface to physical actuators.

Two ways to run

Hosted browser edition

The simulation runs in a browser worker. Each tab owns an independent session. Trace imports are processed in that tab, and the model starts only when the simulator page opens. Export your evidence before reloading or closing a tab.

Local Node edition

The local application serves a simulation and API on your computer, with local session persistence. Multiple clients of that server view its shared run. Run, pause, step, speed and attack controls operate the same underlying model.
